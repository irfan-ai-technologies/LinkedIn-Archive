LinkedIn Archive · Setup Guide

Set up your own LinkedIn Archive on your own domain

A complete, exact walkthrough for taking this repository from a fork to a live personal website — with your LinkedIn posts, your branding, and your own domain name — using GitHub Pages for hosting. No LinkedIn scraping, no server to run, no password stored anywhere.

1 Before you start

You'll need:

  • A GitHub account.
  • A domain name you own (from any registrar — Namecheap, Google Domains/Squarespace, Cloudflare, GoDaddy, etc.) and the ability to edit its DNS records.
  • Optional but recommended for the initial setup: a terminal with git installed, and uv installed (curl -LsSf https://astral.sh/uv/install.sh | sh) so you can preview the site locally before pushing. Everything can also be done through the GitHub web UI plus GitHub Actions if you'd rather not install anything locally — noted inline where that applies.
  • Optional: your own LinkedIn posts, if you want to connect live sync rather than starting with the bundled sample content.
What you will NOT need

Your LinkedIn password anywhere, a server to rent or maintain, or a database. Everything ends up as static files served by GitHub Pages.

2 Fork and clone the repository

  1. Open the repository on GitHub and click Fork (top right). This creates github.com/<your-username>/linkedin-archive under your account.
  2. Clone your fork locally:
git clone https://github.com/<your-username>/linkedin-archive.git
cd linkedin-archive
uv sync

Confirm it works before changing anything:

uv run linkedin-archive build
uv run linkedin-archive serve

Open the printed local URL (typically http://127.0.0.1:8000/) — you should see a working site built from the bundled fictional sample posts.

3 Configure your site

Open config.yaml at the repository root. This is the only file most people need to edit — no Python knowledge required.

Edit the site: section:

site:
  title: "Your Name's Archive"
  description: "A short description of what you write about."
  author: "Your Name"
  url: "https://your-domain.com"          # your own domain — see step 11
  linkedin_url: "https://www.linkedin.com/in/your-linkedin-handle"
  language: "en"
About site.url

Set this to the final custom domain you plan to use (step 10), even before DNS is live — it only affects links baked into the generated pages (canonical URLs, RSS, sitemap), not where the site is actually hosted.

Optionally customize theme: (accent color, dark/light default, how many featured/recent posts to show) and categories: (see docs/configuration.md for the full reference — categories are entirely yours to define, there's nothing hardcoded).

4 Set up your profile / About page

Edit content/profile/profile.yaml:

name: "Your Name"
headline: "Your one-line professional headline"
location: "City, Country"
bio: |
  Write a couple of paragraphs about yourself here. This supports
  Markdown and appears on both the home page and the About page.
avatar: null   # or a URL / path to a photo, e.g. "/static/images/me.jpg"
links:
  linkedin: "https://www.linkedin.com/in/your-linkedin-handle"
  github: "https://github.com/your-username"
  website: ""
  email: ""

If you want an avatar image, add the image file under static/images/ and reference it as /static/images/your-file.jpg.

Prefer to fill this in from LinkedIn directly?

If you request the Profile file in step 7's LinkedIn data export, linkedin-archive import-profile fills in name, headline, bio, and location here automatically — avatar and links still need to be set by hand either way.

5 Get your LinkedIn posts in — three options

You have three ways to populate the archive with your real posts. You do not need to pick immediately — the site works with the bundled sample content in the meantime, and you can switch later.

OptionNeeds LinkedIn API approval?EffortKeeps updating automatically?
A. LinkedIn APIYes — and LinkedIn is not currently accepting new member-social-read access requests at allHigher, one-time setupYes, nightly via GitHub Actions
B. LinkedIn data exportNoLow — request an export from LinkedIn, unzip it, run one commandNo — re-run manually whenever you request a new export
C. JSON importNoLow — you provide a JSON fileNo — re-run manually whenever you have new posts
Recommended starting point

Option B (LinkedIn data export) is the most reliable way to get your real post history in today — Option A's r_member_social permission is closed to new applicants as of this writing, and Option B needs no manual copy-pasting the way Option C does.

Continue to step 6 for Option A, skip to step 7 for Option B, or skip to step 8 for Option C.

6 Option A: connect the LinkedIn API

LinkedIn requires its own review/approval before any app can read a member's own posts (the r_member_social scope, part of a restricted product). This is LinkedIn's policy, not something this project can bypass — and this project never scrapes LinkedIn or stores your password as a workaround.

Currently closed to new applicants

As of this writing, LinkedIn's own Marketing API FAQ describes r_member_social as "closed... [not] accepting access requests... due to resource constraints." You can still fill out the request in step 6.1.4 below in case that changes, but for posts today, use Option B instead.

6.1 Create a LinkedIn developer app

  1. Go to LinkedIn's developer portal and create a new app. LinkedIn requires the app to be linked to a Company Page you administer — create a minimal one if you don't have one already.
  2. In the app's Auth tab, copy the Client ID and Client Secret — you'll need both shortly.
  3. Under Authorized redirect URLs for your app, add: 
    http://localhost:8765/callback
    This is only used for the one-time interactive login on your own machine.
  4. Under the app's Products tab, request the product that grants member-social-read permissions. Fill in whatever LinkedIn's review form asks for and submit. Approval is LinkedIn's process and timeline — this can take time. You can continue every other step of this guide while waiting.

6.2 Set your local secrets

cp .env.example .env

Open .env and fill in:

LINKEDIN_CLIENT_ID=<your client id>
LINKEDIN_CLIENT_SECRET=<your client secret>
LINKEDIN_REDIRECT_URI=http://localhost:8765/callback
Never commit this file

.env is already listed in .gitignore. Double-check git status never shows it before you push anything.

6.3 Authorize once, locally

uv run linkedin-archive auth login

This opens your browser to LinkedIn's consent screen. Approve access, and you'll be redirected back to a small local page confirming success. The resulting token is saved to .secrets/linkedin_token.json (also gitignored).

6.4 Set config.yaml to use LinkedIn

sync:
  provider: linkedin

6.5 Try it locally

uv run linkedin-archive sync
uv run linkedin-archive serve

If your app hasn't been approved yet, this will fail with a clear 403 Forbidden message rather than doing anything unexpected — that's expected until LinkedIn approves your product request. Switch sync.provider back to sample, or use Option B or Option C below, in the meantime.

6.6 Add the same secrets to GitHub, for automated nightly sync

In your fork on GitHub: Settings → Secrets and variables → Actions → New repository secret. Add three secrets:

Secret nameValue
LINKEDIN_CLIENT_IDSame value as in your local .env
LINKEDIN_CLIENT_SECRETSame value as in your local .env
LINKEDIN_TOKEN_JSONThe entire contents of your local .secrets/linkedin_token.json file (open it, copy everything, paste as the secret value)
Why paste a token instead of logging in from GitHub Actions

The interactive OAuth flow needs a browser, which a GitHub Actions runner doesn't have. You authorize once on your own machine, then hand the resulting token to GitHub as a secret. If your app was also granted LinkedIn's offline_access product, the token refreshes itself automatically going forward.

Continue to step 9 (push your changes) — you can skip steps 7 and 8.

7 Option B: import LinkedIn's own data export

This reads the same posts as Option A, but from a file LinkedIn hands you directly instead of through an API that currently isn't approving new access. Nothing here scrapes LinkedIn or automates a browser — it only reads a file already sitting on your disk.

7.1 Request your data export

  1. On LinkedIn: Settings & Privacy → Data privacy → Get a copy of your data.
  2. Choose "Want something in particular? Select the data files you're most interested in", then check Posts (for your post history) and, if you also want step 4's About page filled in automatically, Profile too.
  3. Click Request archive. LinkedIn emails you a download link, usually within a few minutes to a day.
  4. Download and unzip it. Inside you'll find Shares.csv (your posts) and, if you requested it, Profile.csv.

7.2 Import your posts

uv run linkedin-archive import-export path/to/unzipped-export/
uv run linkedin-archive serve

This reads Shares.csv directly — no conversion step needed. It's safe to re-run any time you request a fresh export; posts are matched by their LinkedIn activity id, so re-importing never creates duplicates.

If it can't find or read Shares.csv

The command reports the column headers it actually found, since LinkedIn's export format has changed over the years. See docs/providers.md for details.

7.3 Optional: fill in your About page from Profile.csv

uv run linkedin-archive import-profile path/to/unzipped-export/Profile.csv

This updates name, headline, bio, and location in content/profile/profile.yaml from step 4. It never touches avatar or links — set those by hand, they have no equivalent in a LinkedIn export.

Continue to step 9 (push your changes) — you can skip step 8.

8 Option C: import posts as JSON

Collect your posts (copy them manually, export them, however you prefer) into a JSON file matching this format — save it anywhere, e.g. my-posts.json:

{
  "posts": [
    {
      "id": "1",
      "published_at": "2026-08-20T10:30:00Z",
      "text": "The text of your post here, including #hashtags naturally.",
      "url": "https://www.linkedin.com/posts/your-handle_...",
      "title": "Optional — omit to auto-derive from the first sentence"
    }
  ]
}

Only id, published_at, and text are required per post. Then run:

uv run linkedin-archive import my-posts.json
uv run linkedin-archive serve

This creates one Markdown file per post under content/posts/ and rebuilds the site. Re-run this command any time you have new posts to add — it's safe to run repeatedly (it won't create duplicates).

9 Push your changes to GitHub

git add config.yaml content/ .github
git status   # double check .env and .secrets/ are NOT listed
git commit -m "Configure my LinkedIn Archive"
git push

10 Enable GitHub Pages

  1. On your fork, go to Settings → Pages.
  2. Under Build and deployment → Source, choose GitHub Actions (not "Deploy from a branch").
  3. Go to the Actions tab. If Deploy site hasn't run automatically from your push, open it and click Run workflow.
  4. When it finishes (both the build and deploy jobs green), go back to Settings → Pages — it will show your live URL, something like https://your-username.github.io/linkedin-archive/.
Checkpoint

Open that URL. You should see your configured title, your profile bio, and either your imported/synced posts or the sample posts. If this works, everything through hosting is done — the rest of this guide is about using your own domain instead of the default github.io URL.

11 Point your own domain at the site

11.1 Decide: apex domain or subdomain

Either your-domain.com (apex/root domain) or a subdomain like archive.your-domain.com works. A subdomain is simpler to set up.

11.2 Add DNS records

Log into your domain registrar or DNS provider's dashboard (Namecheap, Cloudflare, Google Domains/Squarespace, GoDaddy, etc.) and add records:

If usingRecord typeHost / NameValue
Apex domain (your-domain.com)A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
Subdomain (archive.your-domain.com)CNAMEarchiveyour-username.github.io

(Optional, for IPv6 on an apex domain, also add AAAA records pointing to 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153, 2606:50c0:8003::153.)

DNS changes can take anywhere from a few minutes to a few hours to propagate.

11.3 Tell GitHub about your domain

  1. In your fork: Settings → Pages → Custom domain, enter your-domain.com or archive.your-domain.com, click Save.
  2. Also add the domain directly to the repository so it survives rebuilds (GitHub's UI writes a CNAME file into the *deployed* output, but since this project rebuilds the site fresh every time rather than committing dist/, commit it yourself so every build includes it):
echo "your-domain.com" > static/CNAME
git add static/CNAME
git commit -m "Add custom domain"
git push
  1. Back in Settings → Pages, once GitHub verifies the DNS record, check Enforce HTTPS (it may be greyed out for a few minutes while GitHub issues a certificate — refresh the page after a bit).

11.4 Update your site configuration to match

Edit config.yaml:

site:
  url: "https://your-domain.com"     # or https://archive.your-domain.com
git add config.yaml
git commit -m "Update site url to custom domain"
git push

This push triggers Deploy site automatically (it watches for changes to config.yaml) and republishes with the corrected canonical URLs, sitemap, and RSS feed.

12 Turn on nightly sync (optional, LinkedIn API only)

If you completed step 6, nothing else is needed — .github/workflows/sync.yml is already scheduled to run nightly and will commit any new posts to content/, which in turn triggers Deploy site automatically.

To change the schedule, edit the cron line in .github/workflows/sync.yml (it uses standard 5-field cron syntax, evaluated in UTC). To trigger it manually at any time: Actions → Sync LinkedIn content → Run workflow.

If you're using Option B (data export) or Option C (JSON import) instead, there's nothing to schedule — just re-run the relevant import command and push whenever you have new posts.

13 Verify everything works

  • Visit your domain — the home page loads with your name, bio, and posts.
  • Open a post directly and confirm the "View original post on LinkedIn" link is correct.
  • Visit /search/, type a word from one of your posts, confirm results appear. Press / anywhere on the site to jump to search.
  • Check /feed.xml and /sitemap.xml load and look like well-formed XML.
  • Toggle dark/light mode with the header button.
  • Resize your browser narrow (or check on your phone) to confirm the layout adapts.
  • Run uv run linkedin-archive validate locally any time you're unsure — it flags malformed content, duplicate post IDs, unknown categories, and broken internal links before you push.

14 Troubleshooting

SymptomLikely fix
Deploy workflow failsOpen the failed run's logs in the Actions tab — linkedin-archive validate runs first and will name the exact content problem.
sync fails with 403 ForbiddenYour LinkedIn app hasn't been approved for member-social-read access yet (and, as of this writing, LinkedIn isn't approving new requests) — use Option B or Option C instead.
auth login never redirects backLINKEDIN_REDIRECT_URI in .env must exactly match an Authorized redirect URL on your LinkedIn app, including the port.
import-export says Shares.csv not foundConfirm you checked Posts when requesting your LinkedIn data export, and point the command at the unzipped folder, not the zip file itself.
import-export or import-profile reports unrecognized headersLinkedIn's export column names have shifted over time; the error lists the headers actually found — see docs/providers.md to extend the recognized aliases.
Pages shows 404 at your domainConfirm DNS records match step 11.2 exactly, confirm static/CNAME contains only your domain with no https:// prefix, and re-check Settings → Pages shows the domain as verified.
HTTPS won't enableWait — GitHub can take a few hours after DNS is correct to issue a certificate. Revisit Settings → Pages later.
Sync workflow can't push new contentCheck Settings → Actions → General → Workflow permissions is set to "Read and write permissions".

For more detail see docs/linkedin-api.md, docs/deployment.md, and the README's Troubleshooting section.
